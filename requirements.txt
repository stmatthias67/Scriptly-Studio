MASTER PROMPT — BUILD A COMPLETE GERMAN HANDWRITING FONT & DIGITAL PAPER WEB APP

1. Your Role

You are a senior full-stack developer, UI/UX designer, software architect, and product engineer. Your task is to build a complete, modern, premium-quality web application that allows users to create their own handwriting fonts, write digital documents in their personal handwriting, customize every aspect of the paper and page design, and export their finished work for use in GoodNotes and other applications.

You must work directly with the existing project and produce a genuinely functional application, not just a design concept or prototype.

Before writing any code, inspect the entire existing project.

Follow these steps in order:

1. Identify the current framework, project structure, entry points, dependencies, existing components, styles, and configuration files.
2. Determine how the application currently starts and builds.
3. Identify which existing files must be replaced, removed, or created.
4. Completely replace the existing application code with a new, clean implementation. Do not simply add a new page to the old application, preserve an outdated interface, or patch the old implementation.
5. Replace obsolete components, old layouts, placeholder screens, and conflicting styles where necessary.
6. Keep only existing configuration, dependencies, assets, and infrastructure that are genuinely useful and compatible with the new implementation.
7. Create all required new files and implement the complete application.
8. Install or update dependencies when the environment allows it.
9. Run the available build, type checks, and tests. Fix errors instead of leaving them unresolved.
10. Verify that the application starts correctly and that the main features work.

Do not delete essential project configuration blindly. Preserve the ability to install dependencies and run the project.

If you have direct access to the project's files and terminal, perform the changes yourself. Do not merely provide instructions or code snippets for me to implement manually.

If something cannot be completed because a required tool, package, backend, or permission is unavailable, clearly explain the limitation and implement the best working alternative.

3. Product Vision

Create a premium web application for people who want to create and use their own handwriting digitally.

The application must allow users to:

- Create a digital font based on their own handwriting.
- Draw individual letters, numbers, punctuation marks, and special characters.
- Preview how their handwriting looks in real sentences and paragraphs.
- Write documents using their custom handwriting.
- Design their own digital paper, notebooks, and page templates.
- Customize text, paper, colors, spacing, layout, and other design details.
- Create multi-page documents.
- Export documents as high-quality images and PDFs.
- Import exported PDFs into GoodNotes and similar note-taking applications.
- Save their documents, font projects, and favorite paper templates.

The experience should feel like a combination of a professional handwriting studio, a digital notebook designer, and a simple document editor.

Working product name: Scriptly Studio

The name, logo, and branding must be easy to change later.

- Letter width

Font generation

If technically supported by the chosen architecture, generate downloadable TTF or OTF font files from the collected glyphs using an appropriate font-generation library.

Requirements:

- Character spacing
- Basic metrics
- Character previews

- Downloadable font file
- Instructions for installing or using the font

Clearly distinguish between a real downloadable font file and an application-specific handwriting rendering system. Never create a fake font download.
